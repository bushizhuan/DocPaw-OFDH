# 后续方向

0.2.0 提供 Java SDK、CLI、原生 OFD 封装、受限 PDF 转换、三类临床 Schema、底层 SM2 签名适配和检查报告。后续工作以接入证据和公开契约的稳定性为优先。

## 优先验证

| 方向 | 需要取得的结果 |
|---|---|
| 不同来源文书 | 可分发的来源样本、不同导出器及实际阅读器的兼容记录 |
| 医院 CA | 已授权非生产环境、具体接口模式、证书链和独立验签结果 |
| 版式与文本 | 独立阅读器的逐页显示、关键文字、字体、坐标及链接核对 |
| 集成与归档 | 独立接入团队验证业务版本、授权、失败恢复及摘要归档 |

## 可扩展能力

- 根据可复现来源文件扩展 PDF 支持范围，保持明确拒绝和回归用例。
- 扩充临床 Schema 及字段映射说明，业务代码体系由接入方明确提供。
- 在有正式协议及符合性样本后推进完整线性化和阅读端互操作。
- 根据实际签署及保存要求评估其他签名封装、可信时间和长期验证材料。

这些方向不构成版本或交付日期承诺。当前支持范围以 [能力与兼容性](implementation-status.md)为准。

## 参与方式

兼容性问题请提供最小可分发来源、版本、预期与实际结果。公共接口或协议扩展先通过 Issue 讨论，贡献流程见 [参与开发](../CONTRIBUTING.md)。真实病历和签署身份通过接入单位自己的受控流程保管，不进入公开仓库。
