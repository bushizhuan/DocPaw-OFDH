# 技术选型

## 运行与交付

构建使用 JDK 21、Maven 3.9，SDK 编译目标为 Java 8。三个 Maven 模块同时提供源码、Javadoc 和运行 JAR；CLI ZIP 保留独立依赖 JAR、许可和 SBOM，便于宿主隔离依赖及审查发行内容。

宿主需要直接调用 Java API 时使用 SDK；旧服务已有冲突依赖或使用其他语言时，可使用 CLI。工具不引入数据库、消息队列或服务框架，调度和业务事务由接入系统管理。

## 文件处理

OFD 读写和签名封装复用 OFDRW，PDF 解析使用 PDFBox。PDF 适配基于受支持的文字、字体、图形和坐标绘制，并保留可检索文字；没有采用将所有页面栅格化的默认转换策略。

当前 PDF 路线是显式受限的静态输入剖面。对 ActualText、缺失字体、未知映射和不支持的图形特性明确拒绝，避免成功返回却丢失内容。独立逐页渲染验收仍需在目标阅读器完成。

## 数据校验

JSON 使用 Jackson，Schema 使用 networknt Draft 2020-12 实现。启用格式断言并限制本地引用，拒绝重复键及外部资源加载。XML 解析禁用 DTD 和外部实体。字段问题输出结构化 JSON Pointer 与中文约束，不回显字段原值。

临床正文可采用项目内置 Schema 或接入方自有规范。Schema 能约束数据结构，业务代码字典和医学含义由来源系统确认。

## 密码与签署

SM2/SM3 运算由 Bouncy Castle 执行。完整签章服务使用 `SignProvider`；底层签名能力通过 `Sm2Signer` 接入，明确选择原文或预摘要模式。固定用户标识和显式返回编码减少不同 CA 协议间的歧义，具体契约见 [CA 接入](ca-integration.md)。

签名值、内容覆盖、证书信任、吊销及可信时间分别记录。文件自带证书不自动成为信任锚。

## 当前主要依赖

| 组件 | 版本 | 用途 |
|---|---|---|
| OFDRW | 2.4.0 | OFD 对象、读写及签名封装 |
| PDFBox | 3.0.8 | 静态 PDF 解析 |
| Jackson | BOM 2.22.4 | JSON 处理与组件版本管理 |
| networknt json-schema-validator | 2.0.8 | 本地 JSON Schema 校验 |
| Bouncy Castle | 1.86 | SM2/SM3、证书及密码运算 |

版本以各模块 POM 为准，完整运行依赖和摘要以发行包 SBOM 为准。Apache-2.0 项目许可、上游 LICENSE/NOTICE 和补充许可随发行保留，见 [第三方清单](../THIRD-PARTY.md)。

## 文件安全与发布

文件包检查覆盖路径、重复成员、中央目录与本地头、CRC、展开预算和链接。输出采用同目录临时文件及不覆盖发布，要求本地文件系统支持硬链接。运行预算不等于进程峰值内存限制，宿主仍需控制并发、堆上限和任务时限。

发行收集核对模块身份、许可原文、ZIP 内外制品及 SBOM 中第三方 JAR 的 SHA-256，防止同版本混装。完整流程见 [发布说明](publishing.md)。
