# 标准适用边界与待补证据

核查日期：2026-10-26。本页记录检查器保留 `NOT_CHECKED` 的依据，不表示这些能力已经实现。源码、实际报告与本文应同时核对。

## ZIP 压缩与线性化

GB/T 48666—2026 的要求可分别核验：

| 条款 | 已明确的要求 | 当前实现与边界 |
| --- | --- | --- |
| 6.1.3 | 支持文档线性化，使用 ZIP 执行；多文件组织符合 ZIP 6.2.0 及以上规范；可压缩内容使用 Deflate | 已有 ZIP 容器检查和 Deflate 写入；可选页面依赖布局优化，完整线性化索引协议仍待核实 |
| 3.13 | 线性化用于改善网络访问；注中描述头部内容索引、优先展示内容及资源前置 | 没有给出可直接据以实现的索引标识、字节布局、偏移字段或互操作协议 |
| 5.3.2(a) | 交换场景按需进行线性化 | 不能据此认定每个尚未线性化的静态文件均违反交换要求，也不能据此宣称软件已经支持线性化 |

默认打包顺序仍是 `OFD.xml` 优先、其余成员按名称排序。启用 `optimizePageOrder(true)` 或 `--optimize-page-order` 后，根据 `Document.xml` 的实际页序及模板、字体、图像、绘制参数、复合对象和批注依赖组织成员，附件正文等剩余内容置后。文件仍只使用既有 OFD 成员与标准 ZIP 中央目录，没有私有头、额外索引文件或偏移扩展字段。具体能力和边界见 [页面布局与渐进读取](page-order.md)。**页面依赖前置是线性化的一部分，不能证明完整线性化格式符合性。** `OFDH-015` 保留 `NOT_CHECKED`。

国家标准修订项目 [20262656-T-244](https://std.samr.gov.cn/gb/search/gbDetailed?id=473E491F83F719DEE06397BE0A0A3FAF) 于 2026-05-22 下达，公开项目说明明确提出在 GB/T 33190 的第 6 章增加“线性化”一节。当前核查到的是修订项目说明，未取得可据以实现的正式索引字节协议；不能把该项目当作已发布的新标准。这里不采用某个阅读器的私有索引，也不以厂商专利或 SDK 接口说明代替主管机构的格式推荐。后续若取得正式协议，需按其版本和独立互操作样本补充实现。

`PKG-002` 是独立的 **DocPaw-OFDH 项目剖面规则**，报告中 `ruleSource.kind=PROJECT`、`clause=null`：按不区分大小写的 `.xml`、`.json`、`.txt` 后缀识别成员，要求其中非空成员使用 ZIP 方法 8（Deflate）。空成员和其他后缀不在其范围内；不据此要求图片、字体等二进制数据重新压缩，也不把压缩率当作标准判据。该规则通过不代表整个 6.1.3 已通过，失败也不等于已证明文件违反该条全部要求。生成器会将输入重新封装为 Deflate；直接检查第三方文件时可能发现项目剖面差异。

GB/T 33190—2016 第 6.1 节规定 ZIP 容器及 ZIP 6.2.0，第 6.2 节给出逻辑文件组织；已核对的 GB/T 42133—2022 文件结构、基本结构和软件章节也未提供线性化索引的字节协议。PKWARE APPNOTE 允许任意成员顺序，并将应用清单的语义交给应用定义。它不能单独证明某种排序具有 OFD 线性化互操作性。ZIP 的“最低解压版本”取决于所用功能；Deflate 成员的值为 2.0 不能直接判为不符合 ZIP 6.2.0 规范。

待补证据：明确适用的公开索引协议、其符合性样本及不同厂商阅读器的兼容性记录。已有页面依赖排序和标准 ZIP 部分读取测试仅证明本实现覆盖的布局能力；自行增加索引文件或 ZIP 扩展字段，也不能直接把 `OFDH-015` 改为通过。

## 长期保存与医疗外部附件

GB/T 42133—2022 第 6 章讨论长期保存处理。其中 6.9(a) 排除图元对象、大纲节点、页面及文档中依赖外部资源的动作；6.12 要求处理扩展信息，将影响显示的内容固化。不能把自定义 `Extensions` 清单直接当成已符合长期保存要求的线性化方案。

同时，GB/T 48666—2026 的医疗专门规定明确保留外部附件机制：7.3(f) 对以外部附件记录的相关医疗数据要求外部跳转链接，7.4(b) 允许内部和外部附件。6.1.2 引用其他标准的“相关要求”，不能据此忽略这些明确的医疗场景规定。

因此，检查器不能发现任何 `URI` 就一律判失败，也不能因链接可以读取就判长期保存通过。需要确认处理用途、附件登记、链接关联的数据类型与适用例外；当前未完成这些判断，`OFDH-021` 保持 `NOT_CHECKED`。PDF 转换保留链接只证明转换行为，不代表已经完成 OFD-H 长期保存验收。工具不会为消除检查问题而静默删除源链接。
