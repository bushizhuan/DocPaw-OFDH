# 契约验证

`tools/validate-design.py` 检查项目的请求契约、文件检查报告和字段校验报告。脚本只读取契约及测试样本，在内存中构造正反例；不生成或修改 PDF/OFD，不访问医院数据库，不执行文件转换或签署。

## 运行

使用 Python 3.10 或更高版本，在独立虚拟环境中安装验证依赖，然后从仓库根目录执行：

```sh
python -m pip install jsonschema==4.26.0 rfc3339-validator==0.1.4
python tools/validate-design.py
```

也可使用 `--dependency-dir` 指定已安装依赖的隔离目录。这些依赖仅用于开发验证，不是 SDK 或 CLI 的运行依赖。

最后已验证的解释器为 Python 3.12.14；解析依赖包括 `attrs==26.1.0`、`jsonschema-specifications==2025.9.1`、`referencing==0.37.0`、`rpds-py==2026.9.1`、`typing-extensions==4.16.0`、`six==1.17.0`。其他解释器和依赖组合以实际运行结果为准。

## 最后已验证结果

| 验证项 | 结果 |
|---|---|
| JSON 解析与重复键检查 | 6 个文件通过 |
| Draft 2020-12 元 Schema 检查 | 3 个契约通过 |
| 正例 | 31 个通过 |
| 反例 | 110 个均按预期拒绝 |

覆盖的反例包括缺少必需字段、类型错误、非法枚举、绝对或越界路径、非法时间、未知签名状态、检查报告计数与汇总不一致，以及字段报告的有效/无效/截断关系、JSON Pointer 转义、实际类型和 100 条上限。

`jsonschema` 的 `format` 检查必须显式启用，并需要可用的 `date-time` 检查器。脚本在格式检查能力缺失时失败，防止只靠日期正则接受不存在的日期。报告汇总、计数和临床字段的确定性对应关系由额外语义断言验证，不宣称所有跨字段关系仅靠 JSON Schema 即可证明。

脚本成功返回 `result=PASS` 和检查计数，失败返回非零退出码。这里的 `PASS` 只表示契约测试通过，不是 OFD-H 文件的整体符合性结论；文件检查报告使用独立的 `assessment` 枚举。

## 证据边界

该脚本不验证 Java 实现、文件容器、页面字体、PDF 转换、密码签署、临床语义或独立阅读器。运行实现的测试与外部验收状态见 [实现与验收状态](implementation-status.md)。

`tests/contracts` 中的材料用于验证协议行为，不作为业务输入模板或运行时默认数据，也不进入二进制发行包。接入方应使用自己的文书来源信息构造请求，字段说明见 [接入说明](integration.md)。
