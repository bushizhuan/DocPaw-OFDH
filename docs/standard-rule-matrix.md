# 标准检查覆盖

当前目录共 28 项执行规则，21 项包含自动检查实现。存在实现不表示对应标准条款的全部细则均已验证；每份报告列出实际结果和未覆盖范围。

标准依据为 GB/T 48666—2026 及适用引用标准。项目增强约束使用 `ruleSource.kind=PROJECT`，标准条款规则使用 `STANDARD` 并记录条款号。正式解释以标准文本和具体应用场景为准。

## 执行目录

| 规则 | 检查范围 | 边界 |
|---|---|---|
| `PKG-001` | ZIP 路径、成员、长度、CRC 和资源预算 | 项目文件安全约束 |
| `PKG-002` | 非空 XML/JSON/TXT 使用 Deflate | 不代表完整 ZIP/OFD 线性化符合性 |
| `OFDH-001`～`004` | 单文档、命名空间/版本、DocType 和文件标识 | 以当前支持的 OFD 1.0 剖面处理 |
| `OFDH-005`、`META-001` | 可识别元数据与项目映射 | 未知第三方映射保留未知 |
| `OFDH-006`～`011` | 页面、资源引用、字体、图像、附件登记及编码 | 不代替独立渲染验证 |
| `CLINICAL-001`～`002` | 临床附件摘要、已声明封套的来源字段一致性 | 不验证完整医学语义 |
| `OFDH-012`～`014`、`SIGN-001` | 签名存在、成员摘要、内容覆盖及受支持格式的密码验签 | 未知签名格式或算法不能作为通过 |
| `OFDH-018` | 显式信任锚下的离线证书链 | 授权、吊销和可信时间仍需外部证据 |
| `OFDH-015`～`017`、`019`～`022` | 完整线性化、独立视觉、临床语义、算法产品适用、版本留存、长期保存及阅读器行为 | 当前未自动证明，保留未检查结果 |

规则定义见 `ofdh-core` 的 `Rule`，报告结构见 [check-report.schema.json](../contracts/check-report.schema.json)。元数据映射见 [架构与数据映射](design.md)。

## 结果含义

逐项结果为 `PASS`、`FAIL`、`NOT_APPLICABLE` 或 `NOT_CHECKED`。汇总结果有三种：

| assessment | 含义 |
|---|---|
| `ISSUES_FOUND` | 本次执行发现失败 |
| `INCOMPLETE` | 没有已知失败，但检查范围或所需证据不完整 |
| `NO_ISSUES_IN_EXECUTED_CHECKS` | 在明确执行范围内未发现问题 |

报告不提供整体标准认证结论。每份报告包含工具版本、规则集版本、文件 SHA-256、覆盖计数、签名状态和限制说明，归档时应与对应文件一起保存。

## 需要外部确认

页面与临床内容的一致性、实际医生授权、吊销状态、可信时间、完整线性化和长期保存依赖业务系统、CA 或独立工具。压缩与外部附件的具体边界见 [标准适用边界](standard-open-questions.md)，试点核对方式见 [接入验收](acceptance-and-release.md)。
