# 接入验收

本文供医院和厂商验证自己的来源、CA、阅读器及归档链路。仓库自动化测试验证实现行为，业务试点还需使用本机构授权材料取得环境证据。

## 验收输入

准备一份来源 PDF 或未签 OFD、同一业务版本的元数据、可选临床 JSON，以及使用的代码体系说明。签署测试使用已授权非生产身份，记录 CA 接口模式、返回编码和信任材料。

先核对 [能力与兼容性](implementation-status.md)及 [CA 接入](ca-integration.md)，避免把当前明确不支持的输入当作转换异常。

## 按链路检查

| 环节 | 核对内容 | 建议保留的证据 |
|---|---|---|
| 请求与临床数据 | 必填、类型、时间、Schema 选择及来源一致性 | 版本化字段映射、脱敏错误报告 |
| 来源冻结 | 页面与数据对应同一业务版本，读取期间来源不变 | 来源版本及 SHA-256 |
| 页面与资源 | 页数、逐页显示、中文及生僻字、字体、图像、坐标和链接 | 独立阅读器版本及逐页核对记录 |
| 机读附件 | 附件登记完整、原字节及摘要一致、正文符合所选 Schema | 附件摘要及临床数据核对结果 |
| 签署 | 身份和授权正确、数据模式与编码匹配、一次实际调用 | CA 任务标识和授权记录 |
| 签后检查 | 原文未变、内容覆盖完整、实际签名值通过、信任锚明确 | 最终摘要、逐项报告及独立验签结果 |
| 归档与恢复 | 文件、版本、索引和报告关联，异常不导致误覆盖或重复签署 | 归档结果及故障恢复记录 |

## 必测失败场景

- 日期无时区、必填缺失、数字字符串、重复 JSON 键或非法 UTF-8。
- 缺少字体或资源、页树计数错误、循环引用及超出预算的输入。
- 来源读取中被修改、输出已存在、报告写入失败及强制取消。
- 错误签署身份、错误 SM2 用户标识、重复摘要、异常签名值和 CA 超时。
- 对已签文档的改写或追加签名请求；检查应按实际范围处理。

失败时核对稳定错误码和实际完成阶段，确保原来源保留、旧文件不被覆盖。文档已生成但报告失败时补做检查，CA 状态不确定时先查询任务，见 [错误处理](errors.md)。

## 放行与回退

接入方根据业务场景决定未覆盖项是否阻断归档。`INCOMPLETE`、`NOT_CHECKED`、未知信任及缺失外部证据不能写成已经通过完整标准验收。

建议先在已有导出和归档链路旁启用独立接入开关。回退时停止新增调用，保留来源、生成文书、签署文件、摘要及审计记录。工具本身没有医院数据库或业务状态迁移。
